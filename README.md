# 馬柱＆予想支援アプリ v5.0

競馬新聞の写真からGeminiが情報を読み取り、Pythonの固定ルールで採点します。
予想のCSV保存・履歴表示と、追加写真による不足情報の再取得に対応しています。

## GitHubに配置するファイル

同じフォルダーに次のファイルを配置してください。

- `app.py`：起動するアプリ
- `history.py`：CSV保存・履歴表示
- `recovery.py`：不足情報の案内・追加写真の再取得
- `requirements.txt`：必要なライブラリ
- `README.md`：使い方
- `scoring_rules.md`：現在の採点ルールの説明

「コピー」を含むバックアップファイルと `gemini-code-1789455600444.py` は起動に不要です。

## 起動

```sh
pip install -r requirements.txt
streamlit run app.py
```

Gemini APIキーはStreamlit Secretsの `GEMINI_API_KEY` に設定します。
未設定の場合は画面の入力欄を使用できます。キーをGitHubに保存しないでください。
モデルは環境変数 `GEMINI_MODEL` で指定できます。

## 画像の登録と予想

1. 全体画像
2. 馬柱・近走成績の拡大画像
3. 調教・追い切り欄の拡大画像
4. オッズ・血統・騎手情報・その他の拡大画像

各欄に同じレースの写真を複数枚登録し、解析ボタンを押します。
馬番・馬名と読み取りたい項目が一緒に写るように撮影してください。
EXIF回転補正、拡大・縮小、軽いコントラスト・シャープ補正を行います。
同じ画像セットの取得結果はセッション内で再利用します。
「同じ画像でもGeminiに再読取させる」をONにして解析ボタンを押すと読み直します。

## 不足情報の追加

不足があれば馬ごとの一覧と撮影方法が表示されます。
「追加写真から不足情報を再取得する」に写真を入れ、更新ボタンを押してください。
再取得に失敗した場合は元の結果を保持します。紙面に情報がなければ追加は不要です。
レース見出し・馬の識別・脚質・枠順は、上部の全体画像に追加して再解析します。
上部の画像セットを変えると別の解析になるため、必要な写真は上部にも含めてください。

### 情報の統合

- 過去走は同じ馬の開催日を軸に、矛盾する項目がない場合だけ空欄を補います。クラス名などが新しく読めても二重計上しません。
- 日付不明・複数候補・項目の矛盾がある過去走は、推測で同一扱いにしません。生データを確認してください。
- 調教は同じコースで時計に矛盾がない場合、既存の時計を保持して空欄を補います。
- 調教日を現在のデータ形式では識別できません。必ず同じ調教の写真を追加してください。別コース・矛盾する時計・コース不明の場合は既存情報を保持します。
- 既存値の誤読を訂正したい場合は、鮮明な画像で上部から再解析してください。

採点式や配点は変更していません。ただし、入力情報が補われると採点結果は変わります。

## 保存・履歴

予想結果の保存ボタンで、アプリと同じフォルダーの `prediction_history.csv` に追記します。
レース日・競馬場・レース番号・馬番・馬名・7採点項目・総合点・印・オッズの15列です。
文字コードはUTF-8 BOM付きです。サイドバーの「予想履歴」で一覧とCSVダウンロードを利用できます。
再取得した結果は保存ボタンを押した時点で保存します。保存のたびに追記されます。
CSVは実行先のローカルファイルで、GitHubへ自動保存する機能はありません。

## 動作確認

全体写真1枚・近走の拡大2～4枚・調教の拡大1～3枚を目安に試してください。
追加写真で不足が補われること、予想保存後に履歴へ表示されることを確認します。
